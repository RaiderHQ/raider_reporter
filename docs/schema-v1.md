# Raider schema v1

`POST /api/v1/runs`, `multipart/form-data`, header `Authorization: Bearer <project token>`.

- Part `payload`: JSON below.
- Parts `att_0`, `att_1`, …: attachment files, referenced by `part`.

```json
{
  "schema_version": 1,
  "client_run_id": "6f1c2a9e-3d4b-4f8a-9b0e-2c7d5e1f8a33",
  "run": {
    "started_at": "2026-10-10T12:00:00Z",
    "finished_at": "2026-10-10T12:04:31Z",
    "ci": { "provider": "github_actions", "build_url": "https://…", "build_id": "123", "attempt": "1", "job": "test", "build_key": "github_actions:acme/app:123:1" },
    "git": { "branch": "main", "commit_sha": "abc123", "commit_message": "Fix login" },
    "environment": { "ruby": "3.4.1", "browser": "chrome", "headless": true }
  },
  "results": [
    {
      "identifier": "./spec/login_spec.rb[1:2]",
      "full_name": "Login with valid credentials logs in",
      "file_path": "spec/login_spec.rb",
      "line_number": 12,
      "status": "failed",
      "duration_ms": 2340,
      "attempts": 2,
      "tags": ["smoke"],
      "failure": {
        "message": "expected …",
        "exception_class": "RSpec::Expectations::ExpectationNotMetError",
        "backtrace": ["spec/login_spec.rb:14:in `block (2 levels)'"],
        "app_frame": "spec/pages/login_page.rb:42:in `submit'"
      },
      "attachments": [{ "name": "screenshot", "part": "att_0", "content_type": "image/png" }]
    }
  ]
}
```

Rules:

- `status` ∈ `passed | failed | pending | skipped`.
- `client_run_id` is a UUID generated by the gem once per suite run; it makes
  uploads idempotent.
- `run.ci`, `run.git`, `run.environment` and every field inside them are optional.
- `run.ci.attempt`, `run.ci.job` and `run.ci.build_key` are optional strings.
  `build_key` identifies the CI build that shards share; on GitHub Actions it
  is `github_actions:<repo>:<run id>:<run attempt>`. Absent outside CI. A
  re-run attempt has a different key, so it is a separate build.
- `run.shard` is optional: `{ "index": <integer >= 1>, "total": <integer >= 1 or null>, "label": "<job or local>#<n>" or "<job or local>#<matrix>.<process>" }`.
  Present only for sharded runs.
- `run.ci.repository` is an optional string, e.g. `"RaiderHQ/demo"` (GitHub Actions: `GITHUB_REPOSITORY`).
- `run.git.default_branch` is an optional string (the repository's default branch).
- `run.git.pr` is optional and present only on `pull_request` and `pull_request_target` events:
  `{ "number": <integer >= 1>, "base_branch": "<string>", "head_branch": "<string>", "head_sha": "<string>" }`.
  On those events `run.git.commit_sha` and `commit_message` describe the PR head commit, not the merge commit.
  On Azure Pipelines it is present for Azure Repos pull requests (`Build.Reason == PullRequest`) and its `number` is the PR id.
  An optional `"url"` (an http(s) string) links to the pull request; it is set by GitHub Actions (`<server>/<owner>/<repo>/pull/<n>`) and Azure Pipelines (`<collection>/<project>/_git/<repo>/pullrequest/<id>`) and omitted when it cannot be built.
- `run.ci.provider` is `github_actions` or `azure_pipelines`. On `azure_pipelines`: `build_url` is the build results page, `build_id` is `Build.BuildId`, `attempt` is `System.StageAttempt` (default `"1"`), `job` is the job display name, `repository` is `"<project>/<repository>"`, and `build_key` is
  `azure_pipelines:<collection host and path>/<project id>/<repository id>:<build id>:<attempt>`. The key uses ids, not names, so renames and names with spaces do not change it.
  `run.shard` comes from `strategy: parallel` (`System.JobPositionInPhase` / `System.TotalJobsInPhase`) when more than one job runs.
- `failure` is present only when `status == "failed"`.
- `failure.app_frame` (optional string, at most 500 characters, added in reporter 0.6.0) is the first line of the raw exception backtrace inside the project root (the working directory when the run starts), skipping `vendor/`, `.bundle/`, installed gems, Ruby's standard library and `<internal:...>` lines. The path is relative to the project root and the rest of the line (line number, `in '...'`) is unchanged. It is taken from the full backtrace, so it can differ from the first line of the (filtered, 50-line) `backtrace`. The key is omitted when no line qualifies or the reporter could not compute it; consumers must then fall back to `backtrace`. Older servers ignore it.
- `attempts` defaults to 1; read from `rspec-retry` metadata when present (RSpec) or counted from Cucumber's `--retry` attempts.
- Test identity: `test_key = SHA256("#{file_path}\0#{full_name}")`, computed by
  the server. `identifier` is stored for display only (it changes on reorder).
- Limits: 50 MB per request, 5 MB per attachment.

Responses:

| Case | Status | Body |
|---|---|---|
| Created | 201 | `{ "run_id": 42, "url": "https://…/projects/x/runs/42", "build": { "id": 7, "url": "https://…/projects/x/builds/7" } }` |
| Duplicate `client_run_id` | 200 | same shape, existing run |
| Missing/invalid token | 401 | `{ "error": "unauthorized" }` |
| Unknown `schema_version` or invalid payload | 422 | `{ "error": "…", "details": […] }` |
| Over size limit | 413 | `{ "error": "payload too large" }` |

The response `build` key is additive; older servers omit it and clients then fall back to `url`.

### Build summary (used by `raider-reporter comment`)

`GET /api/v1/builds/summary?build_key=<run.ci.build_key>`, header `Authorization: Bearer <project token>`.

| Case | Status | Body |
|---|---|---|
| Found (build of this project) | 200 | `{ "state": "passed" \| "failed" \| "incomplete", "markdown": "…", "url": "https://…/builds/7" }` |
| Unknown `build_key` for this project | 404 | `{ "error": "not found" }` |
| Missing/invalid token | 401 | `{ "error": "unauthorized" }` |

The first line of `markdown` is exactly `<!-- raider-reporter:build-comment -->`; the gem uses it to find and update its own comment. The gem sets the commit status `raider/tests` on `git.pr.head_sha` (`passed` → `success`, `failed` → `failure`, `incomplete` → `pending`) with `url` as the target.

The local `raider-results/run.json` uses the same JSON, with `attachments[].path`
(relative to `raider-results/`) instead of `part`. Sharded runs write
`run-<index>.json` and `attachments-<index>/` instead, so readers should load
`run*.json`.


## Cucumber mapping

Cucumber results use the same fields; there is no schema change.

| Field | Cucumber value |
|---|---|
| `file_path` | feature file relative to the project root, e.g. `features/login.feature` (also for `./` and absolute paths) |
| `full_name` | `"<Feature name>: <Scenario name>"`; outline rows `"<Feature name>: <Scenario name> (<Examples name or 'Examples'>, row <n>)"`, `n` = 1-based data row in that Examples table; when several Examples tables of one outline share a label, each is numbered by position among them (`Examples 1`, `Examples 2`) |
| `tags` | feature, scenario and Examples tags, merged, sorted, unique, without `@` |
| `identifier` | `"<file_path>:<line>"` (scenario line, or the Examples row line) |
| `line_number` | scenario line, or the Examples row line |
| `status` | passed→passed; failed, ambiguous→failed; pending, undefined→pending; skipped→skipped |
| `failure.message` | `"<Keyword><step text> (<file>:<line>)\n\n<exception message>"`; `Before hook` / `After hook` replaces the step for hook failures; at most 10,000 characters, UTF-8 scrubbed |
| `failure.backtrace` | at most 50 lines |
| `attempts` | number of attempts under `--retry`; only the final attempt is reported |
| `attachments` | files attached with `RaiderReporter.attach` or Cucumber's `attach(path, media_type)` during the final attempt |
